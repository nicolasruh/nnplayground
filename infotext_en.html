About this App

In this app, you can experiment with simple neural networks: you can modify their data, architecture, or hyperparameters; train the networks; test their performance; and visually inspect their internals. Several sample projects covering classical machine learning tasks are included. You can also create your own custom projects and save or load projects, weights, or data individually using a plain-text JSON structure.

Limits

Since this app runs entirely in your browser, the maximum size of the network architecture is limited (e.g. no more than 11 output neurons and no more than 5 fully connected layers). Even within these limits, training or testing projects with extensive architectures or large numbers of samples can become rather slow. For substantially larger projects or more advanced deep learning architectures, you would need a more powerful environment in which all aspects of the network are defined programmatically.

Similarly, this app only implements the standard supervised learning paradigm. If you want to experiment with other learning paradigms, different activation functions, additional tricks to stabilize learning, or customized workflows, you would need a more advanced setup.

Architecture

The architecture of a neural network defines its structure, including the number of layers, the number of neurons in each layer, and how these neurons are connected. In this app, the architecture is intentionally simple: all layers are fully connected, meaning each neuron receives input from every neuron in the previous layer.

Input layer

The data enters the network through the input layer. Each input neuron corresponds to one value in the input vector.

For example, if the input is a grayscale image, the colour of each pixel can be represented by one number between 0 (= black) and 1 (= white) that is applied to the corresponding input neuron. The values of the input neurons are then passed onward to the next layer.

Hidden layer(s)

Usually, the output layer is reached only after the values have been transformed in the hidden layers. These layers sit between the input and output layers and play a crucial role in forming a useful representation of the task.

A network with more hidden layers can, in principle, have an advantage in learning complex mappings, but deeper networks are also harder to train and more sensitive to initialization, the learning rate, and the choice of activation function. In short: "vanilla" networks usually use only one hidden layer.

Output layer

The output layer contains the final predictions of the network. Its size depends on the task: for binary classification, it may contain a single neuron; for multi-class classification, it may contain one neuron per class (see targets).

Output values are interpreted as predictions, which are then compared with the target values during training and testing.

Weights

Each connection between neurons has a numerical weight. These weights determine how strongly one neuron influences a downstream neuron. During training, the network gradually updates these weights, thus changing the flow of activation through the network and ultimately the resulting prediction at the output layer. The overall behavior of the network is therefore determined by both the architecture and the learned weight values.

Bias nodes

In addition to incoming weighted connections, each neuron can also have a bias term. A bias acts like a constant offset: it shifts the neuron's activation independently of the actual inputs, thus "biasing" the neuron to be active or inactive even when the inputs are zero.

These bias terms are often represented as additional neurons (bias nodes) with a fixed value of 1 and learned weights that represent the individual bias values of the corresponding downstream neurons. For many tasks, the inclusion of bias nodes makes it much easier for the network to learn the desired mapping.

Do not confuse bias nodes with a possible bias in a network's performance. Bias nodes are a structural component of the network, while performance bias refers to systematic errors in the model's predictions.

Deep learning architectures

This app supports architectures with up to three hidden layers. However, since all layers are fully connected, this does not really constitute "deep learning." Instead, it demonstrates that simply stacking multiple fully connected hidden layers often makes learning more difficult rather than more effective. Modern deep learning architectures typically include specialized layers, such as convolutional layers, that perform dedicated preprocessing tasks like feature extraction, edge detection, or spatial filtering. Such architectures are beyond the scope of this app, which is limited to fully connected "vanilla" neural networks.

Data

Neural networks learn from examples. Data refers to the collection of all samples available for training and testing the network. The choice of samples used for training and testing can significantly impact the network's performance and generalization ability.

Samples

Each sample in the dataset requires an input vector that specifies the input values and a target vector that specifies the desired output. In this app, the data is represented in a simple tabular form, where every row corresponds to one sample and each column represents either an input feature or a target value. Additionally, each sample can be designated as either a training sample or a test sample.

It is also possible to edit the data visually using the provided interface. In this representation, colours are mapped to numerical values (e.g. white = 1 and black = 0).

Input & target values

The input values are fed directly into the input layer, which therefore needs one node per input value. Input values range from 0 to 1; intermediate values are possible, but not used in some tasks.

The target values describe the desired output for each sample. The output layer therefore needs one node per target value. They also range from 0 to 1.

Classification tasks usually use binary values to indicate whether a feature or class is present; regression tasks may use continuous values as approximation targets.

Train & test samples

Samples can be marked either as training samples or as test samples. Training samples are used to adapt the weights of the network during training, while test samples are held back and used to assess how well the model generalizes to unseen data.

It is important to keep these roles separate (see Testing): if the model is evaluated on training data only, it may appear to perform very well even when it has not learned the more general task.

Forward propagation

Forward propagation is the process of passing the input of a sample through the network, layer by layer, until the final output is produced. In a fully connected network, every neuron receives values from all neurons in the previous layer, combines them according to their weights, and then passes the result onward. See also Training.

Activation function

To calculate the activation value of a neuron, you first compute the weighted sum of all incoming signals. Then the result is remapped to the range [0, 1] by applying an activation function to this sum.

In this app, the activation function is the sigmoid, or logistic function: \(\sigma(z) = \frac{1}{1 + e^{-z}}\). This basically means that large positive or negative sums are mapped to values close to 1 or 0, respectively, while sums near zero are mapped almost linearly to values around 0.5.

Activation functions are used in neural networks for two reasons: a) repeated normalization of activations prevents values from growing too large, which could destabilize learning; and b) the learning algorithm (backpropagation) requires the network's error function to be differentiable at all points. A sigmoid function fulfils both requirements, as it neatly squashes the weighted sum to a value between 0 and 1 and has a very simple derivative: \(\sigma'(z) = \sigma(z) \cdot (1 - \sigma(z))\).

Prediction

Once the activations have been computed for all neurons in the final layer, the network produces its output, often called a "prediction". This output is then compared with the target values for the current sample. The difference between network output and target (output - target, the error) provides the basis for learning: the weights are adjusted so that the next forward pass brings the output closer to the desired result. See also Training.

Error (loss / cost)

To assess how well the network is performing, we need a measure of how far the predictions deviate from the target values.

The signed error (output value - target value = error) is a good start, but not enough to judge performance in networks with multiple output neurons, because positive and negative errors could cancel each other out.

To assess the network's performance on an individual sample, we calculate half the sum of the squared errors for all output neurons: \(\frac{1}{2}\sum_i (\hat{y}_i - y_i)^2\). This is called the loss of a sample. It is also the measure that the learning algorithm tries to minimize; the factor \(\frac{1}{2}\) simplifies the calculations for backpropagation.

There is yet another level: if we want to evaluate the network's performance during training or testing, it makes sense to consider its performance across all samples. This average loss is called the cost. For example, the cost of an epoch is the average loss over all training samples: \(\frac{1}{N}\sum_{s=1}^{N}\text{loss}_s\).

In summary, the error measures the discrepancy for a single output neuron, the loss measures the total discrepancy for a single sample, and the cost measures the average loss over all samples.

Training

The goal of learning in neural networks is to find a set of weights that makes the network display the desired behavior, that is, produce the correct output for a given input. To achieve this, the network must be trained in an iterative process that repeatedly presents training samples to the network and then adjusts the weights so that the network gets better at producing the desired output.

Epochs

An epoch is one complete pass through the entire training dataset. For example, after 100 epochs, the network has processed each training sample 100 times. Because the order of samples can affect learning, the training data is shuffled before each epoch, so every sample is still presented once per epoch, but in a different order.

Training process

The supervised learning process consists of three basic steps:

  1. First, the input is forward propagated through the network, and the difference between the resulting output and the target is calculated for each output neuron. These errors are combined into the loss for this sample.
  2. Second, the loss is propagated backwards through the network, allowing the contribution of each individual weight to the overall loss to be determined, as well as the direction in which the weight should be adjusted to reduce it (using gradient descent).
  3. Third, the weights are updated accordingly. The learning rate determines how aggressively these updates are applied. The weights may be updated after each individual training sample or after an entire batch of samples has been processed (e.g. after one epoch).

These steps are repeated many times with many different learning samples until, ideally, only a negligible discrepancy remains between the target values and the actual outputs of the network.

Supervised learning

"Supervised learning" means that each training sample is associated with a target, i.e. the desired output for a given input. This target is used to calculate the error of the network's output, which in turn guides the learning process.

There are many different paradigms in machine learning, including reinforcement learning, self-organizing learning, autoencoders, and others. This app focuses exclusively on the most fundamental paradigm: supervised learning with backpropagation.

Backpropagation

Backpropagation is the most common algorithm for training neural networks with supervised learning. Essentially, it consists of comparing the actual output of the network with the desired output (target) and then propagating this error backwards through the network, thus figuring out which weight is responsible for the error and to what extent. Based on this calculation, the weights can be adjusted so that the error for this particular input is minimized.

Gradient descent

Gradient descent is a method for finding the minimum of a function and the principle behind the calculations performed during backpropagation. In the case of neural networks, the function to be minimized is the loss function, which measures the discrepancy between the actual output of the network and the target output.

The goal of training is to adjust the weights of the network in such a way that this loss is minimized for all training samples. For an individual training sample, this can be done by calculating the derivative of the loss function with respect to each individual weight, thus finding the direction in which to adjust this weight. The sigmoidal activation function used in this app has the advantage that its derivative can be expressed in terms of the function itself, which makes the math a lot easier: \(\sigma'(z) = \sigma(z)(1 - \sigma(z))\).

Learning rate

The main difficulty in training neural networks arises from the fact that the derivatives of the loss function tell us how to adjust the weights in order to minimize the loss for a single training sample. However, since we want to minimize the loss for all training samples, we need to find a compromise between the adjustments suggested by each individual sample. This is where the learning rate comes into play. The learning rate determines how aggressively the weights are adjusted based on the calculated gradients. By presenting the training samples repeatedly in random order and adapting the weights only by a fraction (the learning rate) in the direction demanded by each sample, we hope that the network gradually converges to a configuration of weights that minimizes the loss of all training samples.

Choosing an appropriate learning rate can be challenging. If the learning rate is too high, the weights may oscillate or even diverge, preventing the network from converging to a minimum. If the learning rate is too low, training may become excessively slow or get stuck in local minima. Finding a suitable learning rate is crucial for effective learning.

Why learning might fail

In theory, even standard neural networks can learn any mapping between inputs and outputs because it can be proven that there exists a configuration (many, actually) of weights capable of implementing the desired function. However, this does not imply that training will actually find such a configuration. Stable and efficient learning depends on many additional factors, including the network architecture, the initialization of the weights, the choice of activation functions, the learning rate, and the quality of the training data.

Testing

Once a neural network has been trained, it is important to test how it performs and whether it generalises to new inputs rather than just memorizing the training data. Testing is therefore a separate phase in which the model's reaction to various inputs is evaluated, but the weights are not updated.

Testing with train/test data

To evaluate a trained network, it is useful to test it on both the data it was trained on and on data it has not seen before. Testing on training data shows how well the model fits the examples it has learned from, whereas testing on test data reveals whether it can also handle new inputs. These two checks complement each other: the training result indicates how much the model has learned, while the test result shows how well it generalizes beyond the training set.

Overfitting

A model that performs well on the training data but fails on new examples is not very useful: we could have written a "normal" program that simply looks up the input in the data table and gives the corresponding target as output. This would work perfectly with all the training samples, but fail catastrophically as soon as a single input value deviates from the training set. Neural networks can also show this behaviour of simply memorizing the specific patterns from the training set; this is called overfitting. The risk of overfitting is particularly high when the network has many more parameters (weights) than are needed to solve the task. Conversely, limiting the number of parameters forces the network to use more general patterns of similarity between the training samples, which are more likely to be useful for unseen inputs. However, if the network is too small, it may not have enough capacity to learn the task at all. The art of designing a neural network is therefore to find a good balance between these two extremes.

Generalisation

Generalisation is one of the central goals in machine learning, or learning in general. After all, you probably would not claim to have learned to read when in reality you have only memorized a few individual words. Someone who is able to read could be expected to demonstrate this ability by reading new words that they have never seen before. Similarly, a neural network that has learned a task should be able to make correct predictions on inputs it has not seen during training, thus indicating that it has learned something about the underlying rules or regularities of the task.

Testing the network's ability to generalise to novel inputs (test data) is therefore an extremely important aspect of evaluating its performance. As with most aspects of neural networks, however, this is not all or nothing: generalisation might work for some examples but not for others, and we can never prove perfect generalisation because, just like the training set, the test set can only be a hopefully representative selection of examples from the underlying task in general.

Task

A task can often be described quite simply in words, for example "recognise handwritten digits." In practice, however, such a description remains vague: it does not define every possible input that belongs to the task, nor does it specify exactly which variation a model should handle. Even for human readers, we would not expect perfect performance on every conceivable handwritten digit. Except for the most trivial tasks, the problem space is effectively infinite, while a training dataset can contain only a limited selection of examples.

Training samples should therefore cover the relevant variation in the task as representatively as possible. A network that performs well not only on its training samples but also on new, previously unseen examples has generalised. In the best case, its generalisation is as good as, or better than, that of a human observer. This suggests that the network has learned useful regularities underlying the task rather than merely memorizing individual examples.

However, these regularities are not stored as explicit rules that can simply be read from the network. They are represented by the learned weights, that is, a large collection of numbers distributed across the connections between neurons. Even when the network generalises well, it can therefore remain difficult to show directly which regularities it has learned or where exactly they are represented. This is one reason why inspecting activations can be useful, while still providing only partial insight.

Bias

Bias refers to a systematic failure in generalisation that can arise from non-representative data. It is usually introduced when the selection of training samples is skewed and therefore does not represent the task as a whole.

For example, imagine a digit-recognition dataset in which most examples of the digit 1 are written with a small hook at the top. If examples without this hook are rare or absent, the network may learn to treat the hook as an important feature of a 1. It can then perform well on the training data but make worse predictions for equally valid handwritten 1s without a hook. This is not a property of the network itself, but a consequence of training data that does not adequately represent the variation in the task.

Such biases can often be addressed by including more examples that cover this "blind spot" in the training set. However, they may go unnoticed because a skewed data selection is rarely intentional; it often reflects an unrecognized blind spot or bias of the person selecting the data. The same blind spot may then also be present in the testing data. Moreover, it is impossible for a selected set of examples to represent every aspect of a task without any skew. The aim is therefore not to eliminate skew entirely, but to keep it as small as possible.

Inspecting activations

A problematic aspect of neural networks is that, even when they perform admirably at a task, it is hard to understand exactly how they solve this problem, other than the general observation that they have found an appropriate set of weights during the learning process. While a network is not really a black box, as is sometimes claimed, we could maybe call it a grey box: while it is possible to look under the hood and inspect each and every value (this app allows you to do exactly that), it can still be challenging to interpret these values meaningfully.

At its core, this problem is unsolvable: the very essence of this approach is that an individual weight does not perform an identifiable subtask, does not represent anything specific, and has no meaning other than contributing in some small way to the overall workings of the system.

However, there are some techniques that can help to gain insight into the network's behavior. For example, one can visualize the activations of hidden neurons in response to different inputs. This can reveal which features or patterns the network has learned to detect and how it reorganizes the data internally prior to making a final prediction in the output layer.

Most of these techniques are concerned with dimensionality reduction: the hidden layer may be understood as a high-dimensional representation of the input data, so its activation in response to an individual sample is a point in this high-dimensional space. The position of these points can reveal insights into which inputs the network considers similar. See also Data.

Two such techniques are provided in this app:

  • Principal component analysis (PCA) is a way of mapping high-dimensional data to an alternative coordinate system such that the first dimension contains the most variance, the second dimension contains the second most variance, and so on. Visualizing only the first two (PCA 2D) or three (PCA 3D) dimensions should still reveal the most meaningful aspects of the clustering of the data in hidden-layer space.
  • Nearest neighbour is another way of visualizing clusters in hidden-layer space. It involves grouping the points that are closest to one another in a minicluster, then grouping these miniclusters with their closest neighbours into slightly larger clusters, and so on, so that this hierarchical clustering of neighbours reveals the overall structure of the data.
